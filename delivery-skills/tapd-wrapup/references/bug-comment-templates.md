# TAPD 缺陷评论模板

TAPD 评论用 HTML：段落用 `<p>`，小标题用 `<strong>【…】</strong>`，换行用 `<br/>`。下面四个模板按定责结论选一个，按需删掉不适用的小节。

## 前端 · 已修复

```html
<p><strong>【定责结论：前端 · 已修复（{本地分支待提交发版 | 已提交 {commit}} ）】</strong></p>
<p><strong>【问题原因】</strong><br/>{一到三句：哪个页面/组件在什么条件下做错了什么，对应哪个接口或字段}</p>
<p><strong>【修复逻辑】</strong><br/>1. {改了哪个文件/组件，怎么改}<br/>2. …</p>
<p><strong>【验证】</strong><br/>{环境 + 复现步骤 + 修复后看到的结果；补了单测的写用例名}</p>
<p><strong>【测试注意】</strong><br/>{需要回归的相关页面/口径，可选}</p>
```

## 后端问题（前端无需修改）

```html
<p><strong>【定责结论：后端问题，前端无需修改】</strong></p>
<p>{一句话：页面显示的值来自哪个接口的哪个字段，前端处理是对的，错在后端返回}</p>
<p><strong>【验证范围】</strong><br/>环境：{环境标识}；{实际操作范围}<br/>对象：{项目内允许分享的定位线索}</p>
<p><strong>【证据】</strong><br/>1. {接口/操作} 入参：{复现所需的最少字段，脱敏}<br/>2. 实际返回：{字段 = 值}；期望：{字段 = 值，依据}<br/>3. …</p>
<p><strong>【给后端的需求】</strong><br/>1. {具体要改什么}<br/>2. …</p>
<p>{后端修复后前端怎么复验}</p>
```

## 配置/数据问题

```html
<p><strong>【定责结论：配置/数据问题】</strong></p>
<p><strong>【原因】</strong><br/>{缺哪条配置/哪张表的数据/哪个脚本未执行}</p>
<p><strong>【处理建议】</strong><br/>{谁在哪里配什么；需要执行的 SQL 走审批的说明}</p>
```

## 需产品确认 / 非缺陷

```html
<p><strong>【定责结论：需产品确认】</strong></p>
<p><strong>【现状】</strong><br/>{系统现在的行为及其依据（需求原文/既有逻辑）}</p>
<p><strong>【待确认】</strong><br/>{问题}；可选方案：A. … B. …（推荐 {X}，原因 …）</p>
```
