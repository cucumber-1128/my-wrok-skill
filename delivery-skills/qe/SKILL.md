# 原单交给 QE，不自己决定分支

先运行 `qe guide`；命令名或字段不确定时运行 `qe <子命令> --help`。Windows PowerShell 遇到 `qe.ps1` 执行策略限制用 `qe.cmd`。本技能是给 agent 的入口，不安装企业 CLI，也不提供企业登录配置。

1. **认单和认仓。** 用 `qe link "<原始 TAPD 链接>"` 核对项目和迭代，再用 `qe repos` 核对仓库与工作树的 remote。用户给的是缺陷就传缺陷，不手工换成猜测的需求。纯迭代、不挂业务单的事项才按当前帮助显式给项目与迭代；有原单但解析失败不能改成无单。
2. **准备写代码。** `qe branch create "<原单链接>" -r "<仓库>"` 让 QE 按平台规则判定。若返回 `reuse-requirement-branch`，本次没有新建分支：各仓已存在的用返回的需求分支；缺哪个仓，就用 QE 返回的需求为哪个仓申请。独立缺陷的分支类型由 QE 决定，不因标题像线上问题自己造 hotfix。取得平台已有的分支用 `qe git checkout`，在项目映射的独立工作树操作，不挤占别人的主目录。
3. **推送或提 MR。** 按本次授权分别做 `qe git push --cwd "<工作树>"`、`qe mr create "<原单链接>" -r "<仓库>" --reviewer "<审批人>"`。先核对现有 MR、项目目标分支、标题特例，以 `qe reviewers` 返回的候选确认人；不使用原生 Git 创建迭代分支，不改走 GitLab 网页、API 或旧插件。
4. **任务、变更和构建。** 先看 `qe task create --help`、`qe workorder --help` 或 `qe build --help`，只执行本次请求涉及的动作。读单用 TAPD MCP；TAPD 评论、处理人、转测和任务花费交 `tapd-wrapup`。

**需要确认的写操作：** 不带码预览，把本次 QE 输出原样交给用户；收到用户针对它的明确回复，再用相同参数带本次 `--confirm <确认码>` 执行。改参数、对象或仓库就重新预览。预览退出码 0 不等于已写；部分成功只处理未完成项。QE 不可用、登录或权限不满足、候选不唯一时，阻塞该步，不换通道。
