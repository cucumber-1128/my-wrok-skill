# 选能看到这次证据的浏览器

先看**当前宿主的浏览器约定**、项目 `AGENTS.md` / `CLAUDE.md` 和测试阶段规定。项目要求真实接口、指定客户端或指定的登录会话，就保留这些条件，不换成 mock，也不因为另一个工具截图更方便就换浏览器。

| 任务 | 适合的方式 |
|---|---|
| 需要已有登录态（例如授权会话中的业务页面） | 首选宿主与用户共享的浏览器或扩展。指定使用现有 Chrome、已装好且已获授权时，可用连接该配置的 `bsk`；不要直接读取浏览器档案或接管用户其他标签。 |
| 确认本地页面的布局或交互 | 用宿主自带预览或项目支持的浏览器。同一页面检查实际操作后的状态，不以「页面打开」代替验收。 |
| 在测试环境跑一组可重复的浏览器用例 | 使用项目现有的 Playwright、`agent-browser` 等测试入口和测试账号。记录执行版本、实际动作、断言与失败项；只关闭这次创建的会话。 |
| 需要性能或网络证据 | 优先使用项目认可的 DevTools 连接，观察请求状态、相关业务字段、控制台或性能记录。普通截图不能证明服务端返回了什么。 |

**登录与范围**：先核对环境和角色。测试环境有项目批准的一键登录助手时，照项目说明运行，后续操作保持在助手登录的同一会话；没有助手时使用已配置的测试账号和宿主支持的登录方式。遇到扫码、验证码或授权确认，交给用户。预生产、生产用用户授权的登录态，只读取证，不保存、提交或删除业务数据。

选定工具后，同一轮复现尽量使用同一会话。扩展未连接或项目指定的浏览器不可用时，报告缺失条件；只有既符合项目约束、又得到必要授权时才切换。需要读取 TAPD 的正文、评论、附件和截图，使用已配置的 TAPD MCP；业务页面的复现才用浏览器。

**交回证据**：记录环境、版本、角色、操作、实际值与期望值；截图或请求片段尽量只保留相关区域和业务字段。不要把 Authorization、Cookie、会话令牌、个人资料或完整私有原始网络记录带入评论和交接文档。
