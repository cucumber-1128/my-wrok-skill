# 按接收人的下一步选模板

## 给后端：定位到字段

每条写清环境及版本、关联项、页面路径、接口方法与路径、触发前提、实际值、期望值及其依据、对用户的影响。请求要能在接收方测试环境重放；不要用生产数据演示写操作。

> **示例（合成数据）**：测试环境的订单详情显示为「未结算」。样例单 `DEMO-42` 的详情接口返回 `paidAmount: null`；已确认契约规定，已支付时应返回金额（分），未支付时才为 `null`。请核对结算状态和金额字段是否同步；修完用同一状态的测试单重新打开详情。

```sh
curl -sS -H "Authorization: Bearer ${TEST_TOKEN}" \
  "${TEST_BASE_URL}/api/orders/DEMO-42"
```

上例的两个环境变量由接收人在本地设置。多个问题可先给一张「编号 / 接口 / 影响 / 状态」表，再按编号列请求和响应片段。

```text

我方传入：字段 / 类型 / 单位 / 是否必填 / 示例
期望返回：字段 / 类型 / 单位 / 空值含义 / 示例
现有差异：实际请求和响应中的最小相关片段
请确认：哪一方修改、何时切换、双方怎样验收
```

外部系统切换时，并排列出原接口、新接口及兼容期；尚未商定的行为列为「待确认」，不要写成已达成的约定。
