# 达梦项目的 DDL 检查单

先核对目标数据库版本、兼容模式、schema 和同项目已落地的迁移。下面是**一套项目约定**，不是达梦产品的通用限制；若目标仓已有不同约束，以其实际规则为准。只要求审查时给结论和修改点，不执行 SQL。需要迭代工单则交给 QE CLI，使用用户认可的 SQL 文件和平台检测、确认流程。

## 表和字段

- 本约定中库、表、字段名不超过 **32 个字符**；一般业务表建议不超过 **50 列**，大数据宽表按需评估。
- 每张表有主键，约定使用雪花 ID 的项目按其既有 64 位整型字段映射落库。避免数组、自定义类型及 ENUM/SET；短小状态用项目支持的数值类型和明确的值域。
- 依据业务上限给字符串定长。可能接近本项目 **15,000 字符行宽审查线**时，评估把长文本分表并用主键关联；实际可存容量仍取决于数据库版本、页大小和字符编码。
- 精确小数用 DECIMAL，不用 FLOAT/DOUBLE；项目约定金额存**分**、时间存**毫秒时间戳**时用 BIGINT，写清币种、单位及空值含义，不把元或秒直接写进去。
- 字符集与排序规则沿用实例及项目建库约定。不要把其他数据库的 `utf8mb4_general_ci`、`BIGINT(19) UNSIGNED`、位字面量或内联列注释原样套到未经验证的 DM 环境。
- 业务主表按项目标准考虑八个字段：`version`（乐观锁）、`creator_id`、`creator_name`、`create_time`、`modifier_id`、`modifier_name`、`modify_time`、`is_deleted`。默认值、长度、非空约束与现有实体和写入方对齐，避免新增审计列后旧写入失败。

## 索引

本约定使用 `pk_表名`、`uk_表名_字段缩写`、`idx_表名_字段缩写`。约定不用外键约束时，为实际关联字段准备索引，不能用索引替代应用层完整性检查。单表索引数、单个组合索引的字段数都建议控制在 **5 个以内**。

对照真实查询条件设计组合索引，不为每个 AND 条件各建一个。优先考虑常用等值过滤前缀，范围条件放后；短字段是否放左边还要看选择性、排序和真实执行计划。已有 `(a,b,c)` 时检查 `(a,b)`、`(a)` 是否有独立用途；主键上也不要重复建相同索引。判断冗余是评估，不自动删现有索引。

## 用 COMMENT ON 标明业务含义

示例仅演示 DM 的表注释和列注释写法；实际迁移沿用项目的 schema、标识符大小写及引号策略。

```sql
CREATE TABLE DEMO_RECORD (
    ID BIGINT NOT NULL,
    CONSTRAINT PK_DEMO_RECORD PRIMARY KEY (ID)
);
COMMENT ON TABLE DEMO_RECORD IS '演示记录';
COMMENT ON COLUMN DEMO_RECORD.ID IS '记录主键';
```

检查每个新增字段是否有注释；金额、时间、枚举状态尤其要写清单位或取值。回报时分开列「已通过 SQL 文本核对」与「已用目标实例或平台验证」，没有真实实例结果时不宣称可在现场直接执行。
