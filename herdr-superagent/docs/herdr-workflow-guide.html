一句话交办需求和缺陷

在 Claude Code 或 Codex 的对话里说“启用 SuperAgent 模式”，然后贴 TAPD 链接或附上 Excel。这个对话就是入口，不用自己开 Router、跑命令或选模型。

01 /

发链接，或者把缺陷表拖进对话

做一个或多个需求
启用 SuperAgent 模式做需求：〈TAPD 需求链接〉、〈另一个需求链接〉。做到可提交，不推送。

只有一个就发一个。没有 TAPD 单也可以描述具体需求；系统不会替你编一个单号。

修一批缺陷
启用 SuperAgent 模式，修一波 bug，链接在附件 Excel 里。

直接附 .xlsx / .xlsm，也可以粘贴多条缺陷链接，或文件、链接一起发。只做部分行时说清表名和范围。系统去重、按工作区分项目，用 TAPD 读取原单，不改原表。旧 .xls 请先另存为 .xlsx。

普通用户无需准备清单或配置。项目认不清、链接无权限、附件读不到，只问对应项；其余能做的继续。想限制范围，就在同一句加“只分析”“只改后端”或“不要发版”。

如果我只是想看进度呢？

说“启用 SuperAgent 模式，只按现有报告汇总这几条的进度，不要重测”。入口只读原记录。批次里会分开列待办、在做、已交回和受阻；收进清单不代表已修复。一个批次可以有多个需求，不必强行并成一条项目任务。

02 /

你对接一个入口，不用盯每个窗口

  1. 入口Router
    判断是问现状、续办已有需求，还是开始新委托。简单问题直接答；多项需求在这里分流。只做一项完整需求时，也可以直接找 leader。
  2. 负责人Leader
    找出项目原任务、依赖、验收和停止点。一项需求用一条 Thread（任务线）串起多个仓库：读规则去项目根，写代码只去任务登记的独立工作树，不另造一套任务表。
  3. 执行与复核Workers
    开发做改动和自测，复审独立看风险，测试按授权验证。不同工作树可并行，同一个工作树只安排一个写入者。已有项目审查步骤，不再为相同目的多审一轮。
  4. 回到入口Handoff
    负责人把结论、版本、证据和未完成项交回来。有产品口径或权限需要你决定时，告诉你具体问题；不会用模型猜测替你拍板。
有 MR、CI 消息，或者任务卡住时呢？

配置了 Trigger 才会采集外部消息。事件先存入本地队列，有运行中的负责人就交给他，无主事件交 Router。后台 driver 接续待启动任务、投递事件、观察状态；可选的语义 Watchdog 分析异常。外部评论可以提供线索，不能替你授权。消息显示“已投递”也不等于执行者已接单，更不等于工作完成。

03 /

主控和浏览器固定，开发与复审可互换

一句话入口自动给后续派工选 delivery，不用报模型名。当前对话负责接单，沿用自己的模型；下表是随包样例，实际使用须先在本机提供方配置好这些模型别名或替换为可用别名。模型是干活的引擎，Codex 和 Claude Code 是提供工具的客户端。

主控、跨仓裁决CodexGPT‑6.2 Astracodex/gpt-6.2-astra
开发、自测、重构Claude Code提供方自动路由group/group

“这轮开发和复审互换。” 新流程选 delivery-swapped：SWE‑2 开发，自动路由复审。只换模型，不换职责、权限和验收标准。可用模型和自动路由策略取决于你的提供方配置。

什么时候用 Sol？ 已有脚本能断言的回归直接跑脚本。需要真人视角操作页面时，负责人给新测试会话传 -Purpose browser，用项目指定的浏览器工具。例如保存审批后重新打开单据，核对状态和权限，而不是只凭“保存成功”提示判通过。

PowerShell：只预览模型配置
$sa = "$HOME/.claude/skills/herdr/scripts/sa-state.ps1"
pwsh -File $sa profile show --workflow-profile delivery
pwsh -File $sa profile show --workflow-profile delivery-swapped

两条命令只展示配置，不启动模型。启动时由入口选 -WorkflowProfile；子任务继承本轮快照，已有会话不会因改配置而换模型。

04 /

做事按项目，迭代走质效平台

Router 先到项目规则根目录找适用于这张单的工作流；工作树里没找到，不代表项目没有。项目有流程就接续原阶段；确认没有适用流程时，需求走全局 req-closeloop，缺陷走 bug-closeloop。 已有项目流程但入口不可用，或还没获准进入下一阶段，就停在那一步。

按任务表协作 · OpenSpec

看清任务依赖，不等于开工

“只分析这条需求的导入和预览能否并行，不开工。”

读原任务表和工作树映射。接口已定稿的部分可以并行，等待前置结果的部分列出依赖。项目要求明确点名实施阶段，就不会从分析自动进入写代码。

跨仓需求 · 前后端接力

两个仓库，不必全员互等

“按已审方案做前后端，只用需求工作树，做到可提交就停。”

沿用项目实施流程和原任务号。接口已定稿的前端任务可与后端并行；未定稿的只等自己的契约。负责人统一更新交付清单。只授权后端时，报告前端影响而不改前端。

分支和 MR 只由 QE 办。 你发的是 bug，负责人就把这张 TAPD 缺陷原单和目标仓交给 qe。若 QE 判定关联需求，已有需求分支直接复用；某个仓还缺，则按 QE 返回的需求为那个仓申请。独立缺陷也按 QE 的方案走，不让 agent 自拟名字、用 Git 建分支。

“做到可提交”就停在可提交。你要求提 MR 时，负责人用 QE 核对源分支、目标和审批人，先展示平台预览；你确认这份预览后，才执行对应操作。预览参数变了要重新确认，不能改走 GitLab 网页或其他工具。批量单据中拿不准的一项单独等你，不耽误其他项。

05 /

看证据，也看它停在哪里

一份合格的回报：改了什么、对应哪个版本、实际跑了多少用例、哪些失败或跳过、证据在哪里，以及这次有没有提交或发版。
本轮交回
HANDOFF
做到了你约定的停止点。例如“可提交，真机 16/18，两项跳过”。这可以是一次完整的进度汇报，但不是全部用例通过，也不是已提交或已发布。
等你 / 暂停
WAITING_HUMAN 是需要你作决定，PAUSED 是已暂停，BLOCKED 是暂时无法推进。你说“停测，给我交接”，交回的应是现有证据、缺口和下一步，而不是又跑一轮。
完整验收
CLOSED
通用完整开发链要经过实现完成、复审通过、确认当前运行版本、测试通过，负责人终审后才关闭。项目专用委托按原项目规则交回，不用凑齐一排 PASS 才能结束。
